## Gitignore Patterns

### Python
```
__pycache__/
*.py[cod]
*$py.class
*.so
.Python
```
**Why**: Generated bytecode, compiled extensions

---

### Virtual Environments
```
venv/
.venv/
env/
ENV/
```
**Why**: Each developer has their own environment

---

### Secrets
```
.env
.env.local
.env.*.local
```
**Why**: Contains API keys, passwords  
**⚠️ CRITICAL**: Never commit `.env` files

---

### Generated Output
```
hiring_cafe_jobs.json
hiring_cafe_by_ats.json
dry_run_payload.json
```
**Why**: Generated at runtime, may contain sensitive data

---

### Browser Data
```
chrome_profile/
chrome_profile_worker*/
```
**Why**: Large files, user-specific, recreated on startup

---

### Logs
```
*.log
logs/
*.log.*
```
**Why**: Generated at runtime, may be large

---

### Databases
```
*.db
*.sqlite
*.sqlite3
*.duckdb
```
**Why**: Generated data, may be large

---

### Test Artifacts
```
.pytest_cache/
.coverage
htmlcov/
```
**Why**: Generated by test runners

---

### IDE/Editor
```
.vscode/
.idea/
*.swp
*.swo
.DS_Store
```
**Why**: Editor-specific, personal preferences

## What to Commit

### ✅ Always Commit

**Source code**:
- `*.py` files (all Python source)
- `scripts/*.py`
- `strategies/*.py`
- `core/*.py`

**Configuration templates**:
- `config/settings.py`
- `config/hiring_cafe.json`
- `config/hiring_cafe_locators.json`

**Documentation**:
- `README.md`
- `CLAUDE.md`
- `docs/**/*.md`

**Dependencies**:
- `requirements.txt`

**Scripts**:
- `start.sh`
- `start.ps1`

**Tests**:
- `tests/*.py`

**Version control**:
- `.gitignore`

---

### ❌ Never Commit

**Secrets**:
- `.env` ← Contains API keys
- Any file with passwords/tokens

**Generated data**:
- `hiring_cafe_jobs.json` ← May have 100+ MB
- `hiring_cafe_by_ats.json`
- `logs/*.log` ← Can grow indefinitely

**Browser data**:
- `chrome_profile/` ← Can be 100+ MB
- User-specific browser settings

**Python cache**:
- `__pycache__/`
- `*.pyc`

**Large binaries**:
- Databases (*.db, *.sqlite)
- Chrome installers

---

### ⚠️ Maybe Commit (Case by Case)

**Sample data** (for testing):
```python
# Create sanitized sample
sample_jobs = {
    "jobs": [
        {
            "job_id": "sample123",
            "title": "Sample Engineer",
            "company": "Sample Corp",
            "ats_url": "https://example.com/apply"
        }
    ]
}
# Save as tests/fixtures/sample_jobs.json
```
✅ Commit if: Small (<10 KB), no real data, useful for tests  
❌ Don't commit if: Real job data, company names, URLs

**Config with defaults**:
```python
# .env.example (safe to commit)
AUTH_URL=https://api.example.com/login
AUTH_USERNAME=your_username_here
AUTH_PASSWORD=your_password_here
HEADLESS=false
```
✅ Commit `.env.example` with placeholders  
❌ Don't commit `.env` with real values

## Common Scenarios

### Scenario 1: Just added a new feature
```bash
git status
# M  strategies/custom/hiring_cafe.py
# M  scripts/hiring_cafe_step2_extract_ats_urls.py
# ?? tests/test_new_feature.py

git add strategies/custom/hiring_cafe.py
git add scripts/hiring_cafe_step2_extract_ats_urls.py
git add tests/test_new_feature.py

git commit -m "Add status tracking to ATS extraction

- Track 7 distinct failure types (timeout, browser_error, etc.)
- Retry retryable failures up to 3 attempts
- Add tests for resume logic

Co-Authored-By: Claude Sonnet 4.5 <noreply@anthropic.com>"
```

---

### Scenario 2: Accidentally added .env
```bash
# DANGER: .env was added
git status
# ?? .env

# DON'T DO THIS:
# git add .env  ← NEVER

# Instead:
echo ".env" >> .gitignore
git add .gitignore
git commit -m "Ensure .env is ignored"
```

**If already committed**:
```bash
# Remove from git but keep local file
git rm --cached .env
git commit -m "Remove .env from version control"

# Force push if already pushed (⚠️ dangerous)
# git push --force
```

---

### Scenario 3: Large generated files
```bash
git status
# ?? hiring_cafe_jobs.json  (150 MB)

# Check if already in .gitignore
grep "hiring_cafe_jobs.json" .gitignore
# hiring_cafe_jobs.json  ← Already ignored, good!

# Git won't track it (no action needed)
```

---

### Scenario 4: Want to share config
```bash
# Create template version
cp .env .env.example

# Remove sensitive values
sed -i 's/=.*/=your_value_here/' .env.example

# Commit template
git add .env.example
git commit -m "Add environment template"

# Original .env stays ignored
git status
# ?? .env  ← Still untracked (good)
```

## Best Practices

### 1. Check Before Committing
```bash
git diff                    # Review changes
git status                  # Check untracked files
git add -p                  # Stage interactively
```

### 2. Write Good Commit Messages
```
Add status tracking to ATS extraction          ← Summary (50 chars)
                                               ← Blank line
- Track 7 distinct failure types               ← Details
- Retry retryable failures up to 3 attempts
- Add tests for resume logic

Fixes #123                                     ← Issue reference
```

### 3. Commit Related Changes Together
✅ **Good**: Feature + tests in one commit  
❌ **Bad**: Mixing unrelated fixes

### 4. Never Commit Secrets
Use environment variables:
```python
# ✅ Good
import os
api_key = os.getenv("API_KEY")

# ❌ Bad
api_key = "sk-1234567890abcdef"  # Don't hardcode!
```

### 5. Keep Commits Atomic
One logical change per commit:
- ✅ "Add dry-run mode to step4"
- ❌ "Fix bugs and add features"

### 6. Test Before Committing
```bash
python tests/run_all_tests.py  # Run tests
python -m py_compile file.py   # Check syntax
```

## Branch Strategy

### Main Branches
- `main` - Production-ready code
- `dev` - Integration branch

### Feature Branches
```bash
git checkout -b feature/status-tracking
# Make changes
git commit -m "Add status tracking"
git push origin feature/status-tracking
# Create PR: feature/status-tracking → dev
```

### Naming Convention
- `feature/` - New features
- `fix/` - Bug fixes
- `docs/` - Documentation only
- `refactor/` - Code cleanup
- `test/` - Test additions

## Cleaning Up

### Remove Untracked Files
```bash
# See what would be deleted
git clean -n

# Remove untracked files
git clean -f

# Remove untracked files + directories
git clean -fd
```

### Undo Uncommitted Changes
```bash
# Discard changes to a file
git restore file.py

# Discard all changes
git restore .

# Unstage a file
git restore --staged file.py
```

### Fix Last Commit
```bash
# Add forgotten file to last commit
git add forgotten_file.py
git commit --amend --no-edit

# Change last commit message
git commit --amend -m "New message"
```

## Pre-Commit Checklist

Before every commit:

- [ ] Run tests: `python tests/run_all_tests.py`
- [ ] Check syntax: No import errors
- [ ] Review changes: `git diff`
- [ ] No secrets: Check for API keys, passwords
- [ ] No large files: Check file sizes
- [ ] .gitignore updated: New patterns added if needed
- [ ] Commit message: Clear and descriptive

## Emergency: Committed Secrets

If you accidentally committed secrets (API keys, passwords):

### 1. Remove from history (DANGEROUS)
```bash
# Remove file from all commits
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch .env" \
  --prune-empty --tag-name-filter cat -- --all

# Force push (⚠️ coordinated with team)
git push origin --force --all
```

### 2. Rotate credentials
**CRITICAL**: Assume credentials are compromised
- Change API keys immediately
- Reset passwords
- Revoke tokens

### 3. Notify team
- Alert teammates
- Document incident
- Update security procedures

## Git Commands Reference

### Status & Info
```bash

git log --oneline       # Show commit history
```


```bash

```

## Troubleshooting

### "Everything is committed but git status shows changes"

**Cause**: Line ending differences (CRLF vs LF)

**Fix**:
```bash
# Configure git to handle line endings
git config core.autocrlf true    # Windows
git config core.autocrlf input   # Mac/Linux

# Refresh index
git rm --cached -r .
git reset --hard
```

---

### "Can't push - remote has changes"

**Cause**: Remote was updated since last pull

**Fix**:
```bash
git pull --rebase       # Rebase your changes
git push                # Push again
```

---

### "Accidentally committed to main instead of feature branch"

**Fix**:
```bash
# Create branch from current commit
git branch feature/my-work

# Reset main to before your commits
git checkout main
git reset --hard origin/main

# Continue work on feature branch
git checkout feature/my-work
```
